# Troubleshooting Glyf

Use the [setup instructions](../README.md#development-environment) and [user guide](user-guide.md) alongside this page. If a document is still open, download accepted changes before restarting the viewer. Invalid file opens and failed exports preserve the current document; refreshing does not.

## Setup and startup

Run commands from the repository folder containing `package.json`. Use `node --version` and `bun --version` to check the executables your terminal actually finds.

| Symptom                                                    | What to do                                                                                                                                                                                                                                                                                                                                     |
| ---------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `bun` or `node` is not found                               | Install the required tool and open a new terminal. If installed but absent from PATH, follow its installation instructions; Bun documents [PATH setup](https://bun.sh/docs/installation).                                                                                                                                                      |
| Installation says to use a different Bun or Node version   | Select Bun **1.3.14** and a Node version in the [declared range](../package.json). Node **22.18.0** is the locally verified choice; with nvm installed, run `nvm install` and `nvm use` in the repository. Recheck both version commands before retrying.                                                                                      |
| Frozen lockfile error                                      | The checkout's manifest and lockfile may not match. Use matching `package.json` and `bun.lock` from the same revision. If you intentionally changed dependencies, use the documented [dependency-maintenance procedure](../README.md#dependency-maintenance) and review the resulting changes. Do not delete the lockfile to bypass the error. |
| Registry/network download fails                            | Restore access to the package registry and retry `bun install --frozen-lockfile`. Installing tools, packages and browser-test binaries needs connectivity even though document processing works locally.                                                                                                                                       |
| Missing package, tool binary or generated validator        | Finish the frozen install with lifecycle scripts enabled, then use `bun run dev`, `bun run build` or `bun run test`. These commands generate the validator automatically. If an existing installation is damaged, stop project processes, remove only this checkout's disposable `node_modules`, and reinstall from the frozen lockfile.       |
| Local URL does not open                                    | Check that the terminal server is still running and open the exact Local URL it printed. Vite may choose another development port if the default is busy. The default server listens on this computer's loopback interface; that URL is not a shared public or phone-accessible deployment.                                                    |
| The chosen port is already in use                          | Stop your earlier project server with Ctrl+C, or choose another port: `bun run dev --port 5180 --strictPort`. For a production preview, use `bun run preview --port 4181 --strictPort` after building. Open the corresponding printed URL.                                                                                                     |
| Preview reports no build, or displays old application code | Run `bun run build` before `bun run preview`; rebuild after code changes. Preserve any open document edits before reloading. Do not open `dist/index.html` directly.                                                                                                                                                                           |
| Browser tests cannot find a browser executable             | After dependency installation, run `bun run playwright install --only-shell chromium webkit`. On Linux CI, the [workflow](ci.md) uses `--with-deps` to install system prerequisites too. This is for automated tests; normal viewing uses your own browser.                                                                                    |
| `bun test` gives unexpected failures                       | Use `bun run test` to run the project's Vitest suite, or `bun run test:viewer` for production browser tests.                                                                                                                                                                                                                                   |

## Opening files and reading errors

Choose **one `.glyf` file** at a time. The viewer reads actual content; renaming a PDF or ZIP to `.glyf` does not convert it. If your file picker filters it out, check the saved filename and suffix. Keep the original while investigating a damaged file. The JSON version field must be `"glyf": "0.1.0"`. The earlier `mosaic` marker is not supported: an error at `/glyf` can mean you opened a pre-rename document. Renaming its suffix alone does not convert it. Both markers together also fail; start from the current Glyf example when authoring a new document.

The error panel identifies **Could not open** or **Could not download**, the attempted filename when available, and a readable message. Format validation failures also include an error code and a **JSON Pointer**; browser read/download failures may have only a retry message. The pointer identifies a location inside the JSON, not a line number. For example, `/datasets/revenue/rows/0/amount` refers to the first revenue row's amount (`0` is the first array index). `""` means the document root. In a property name, `~1` represents `/` and `~0` represents `~`. The validator stops at the first applicable failure, so another error can appear after the first is corrected.

| Error or message                                 | Meaning and next step                                                                                                                                                                                                                                |
| ------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FILE_TOO_LARGE` on open                         | The input exceeds 5,242,880 bytes, including any BOM. Ask the author for a smaller document or reduce it in a separate authoring tool. The viewer does not raise the limit.                                                                          |
| `INVALID_UTF8`                                   | The bytes are not valid UTF-8. Ask the source application to export UTF-8 JSON; replacing unreadable characters blindly can lose data.                                                                                                               |
| `INVALID_JSON`                                   | JSON is malformed, truncated, contains duplicate properties, or otherwise cannot be parsed safely. Obtain a complete copy or correct it in a text/JSON editor. An optional single leading UTF-8 BOM is accepted; repeated or misplaced BOMs are not. |
| `UNSUPPORTED_VERSION`                            | The document declares a version other than `0.1.0`. Use a compatible viewer or ask for a v0.1 export. Editing only the version marker is not a migration.                                                                                            |
| `SCHEMA_ERROR`, `INVALID_ROOT` or `DUPLICATE_ID` | The document structure, root or identifiers violate the format. Give the author the message and pointer; use the [format contract](compatibility.md) to correct the underlying data.                                                                 |
| `INVALID_BINDING` or `INVALID_DATASET`           | A control/chart references incompatible or missing data, a row is incomplete, or a dataset rule fails. Check the referenced state, columns and rows with the document author.                                                                        |
| `RESOURCE_LIMIT`                                 | A document resource exceeds its fixed ceiling, such as node count or plotted points. Hidden content also counts. See the [resource limits](compatibility.md#fixed-resource-limits); toggling content off does not remove it from the file.           |
| “The file could not be read”                     | Choose the file again. Ensure it still exists and is readable; for a cloud-backed file, make a complete local copy first.                                                                                                                            |
| “Drop one Glyf document at a time”               | Retry with one file. The current document remains open.                                                                                                                                                                                              |

These corrections belong in the source/authoring tool: the viewer's Source tab is read-only. Cancelling a chooser or rejecting an incoming file preserves the current document and edits, so you can still download the open document while investigating another file.

## Editing and display

| Symptom                                      | What to do                                                                                                                                                                                                                                                                                                                   |
| -------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A cell cannot be edited                      | Its table and column must both allow editing. Use enabled controls or ask the author for an editable version. There is no viewer switch that overrides document permissions.                                                                                                                                                 |
| A numeric field shows feedback               | Enter a finite number using a decimal point, without currency symbols or grouping commas. Complete partial forms such as `-` or `1e`. Press Escape in the field to restore its last accepted value. Clearing a numeric field is an invalid draft; use the table cell's **No value** option when a missing value is intended. |
| A chart did not change while typing          | An invalid/rejected draft leaves the last accepted data unchanged. Correct the input and read any field feedback. Rows with No value in a plotted coordinate are skipped; a hidden chart can still impose the 500-point limit.                                                                                               |
| A chart or section disappeared               | A document control can hide conditional content. Restore the relevant setting if one is available. Hiding content does not delete its accepted data or exclude it from Download.                                                                                                                                             |
| Only 100 table rows are shown                | Use **Show … more rows**. Source and downloads contain all rows even before you reveal them.                                                                                                                                                                                                                                 |
| An image, HTML block or link does not render | Images and raw HTML are disabled, and link targets are restricted. This is expected policy, not a missing download. Deep or difficult Markdown can display its escaped source as a fallback.                                                                                                                                 |
| A layout looks crowded on a small screen     | Scroll within wide tables or code blocks. Browser zoom and larger text are supported by automated layout checks, but physical mobile browser coverage remains incomplete.                                                                                                                                                    |

## Download and saving

| Symptom                                                   | What to do                                                                                                                                                                                                                                                                                                                                                      |
| --------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Download is disabled                                      | Open a valid document first, or wait for an in-progress file read to finish.                                                                                                                                                                                                                                                                                    |
| “Could not download” with `FILE_TOO_LARGE`                | The formatted export exceeds 5 MiB, even if the compact input fitted. Shorten editable content and retry if that is sufficient. Source can still show the current values for copying to a separate editor. Structural reduction, such as removing rows or splitting the document, needs an external authoring tool; the viewer has no row-delete/split command. |
| Another validation error prevents Download                | The current document remains available. Use its message and pointer to identify the problem, and preserve Source/current values before changing or restarting anything.                                                                                                                                                                                         |
| “The download could not be started”                       | Keep the tab open and retry. Check browser download controls. If the issue persists, preserve accepted values from Source before investigating browser-specific behavior.                                                                                                                                                                                       |
| Unsaved changes cleared, but no file is visible           | That label clears when a download starts. Check the browser's downloads list, save dialog, cancellation status and destination folder. Download again if necessary.                                                                                                                                                                                             |
| The original file still has the old values                | Expected: Download creates a new file. Reopen the downloaded copy; a browser may have renamed it to avoid a collision. Open Demo always opens the bundled original example.                                                                                                                                                                                     |
| A value in the download differs from what you were typing | Only accepted values are exported. Resolve invalid numeric feedback before saving. JSON export also normalizes whitespace and number spelling.                                                                                                                                                                                                                  |
| Edits disappeared after refresh/close                     | The viewer has no autosave or session recovery. Reopen the most recent completed download; undownloaded in-memory edits are not recoverable through this viewer.                                                                                                                                                                                                |

## When asking for help

Record the action attempted, browser/OS versions, error message/code/pointer, and whether a current document remained open. For setup failures, include Node/Bun versions and the failing command. A small reproducible document is more useful than a screenshot alone; remove private content before sharing it. Do not assume an error report needs the whole original file.

The [known limitations](user-guide.md#known-limitations) distinguish unsupported features from failures. The [CI guide](ci.md) explains automated test reports, and [release readiness](release-readiness.md) records unresolved browser, memory and public-release checks.
