# Glyf viewer 0.1.0-rc.2 — draft release notes

Prepared **2026-11-22** for local evaluation. Glyf is the user-selected product name, with the tagline **One format. Infinite expressions.** The app version is **0.1.0-rc.2**; the supported document marker remains exactly **`"mosaic": "0.1.0"`**. This is a draft candidate, not a published release.

## Changed since rc.1

- Rename the viewer, browser title, current guides and bundled demo to Glyf.
- Download `.glyf` files; accept both `.glyf` and legacy `.mosa` through Open File. Drag-and-drop continues to validate content. Reopening a downloaded file preserves datasets, state, conditions and structure.
- Preserve the format contract, serializer, schema bytes and TypeScript API names. No document migration is required, and a `glyf` JSON version field is not accepted as an alias.
- Package under `glyf-viewer-0.1.0-rc.2`, with `glyf-demo.glyf` and the unchanged schema bytes named `glyf-v0.1.schema.json`. Preserve rc.1 artifacts and the original supplied reference material.

## Included

- Open the built-in demo, choose a local file, or drop a file into the viewer. Switch between rendered Preview and read-only Source. Structured failures show the validator's message, error code and JSON Pointer while preserving the current document.
- Render all 14 v0.1 node types: layouts, headings, text, safe CommonMark, dividers, tables, bar/line charts, controls and conditional content. Tables use labeled headers and reveal rows in batches of 100. Charts include summaries, negative values and missing-data handling.
- Edit permitted table cells and saved state. Valid changes update charts, displayed values and conditions immediately; invalid drafts retain the last valid value and show feedback.
- Download the current accepted document, reopen it and retain edits. Modified documents require confirmation before replacement through Open Demo, Open File or drop.
- Enforce strict UTF-8/JSON reading, duplicate-property rejection, schema and semantic validation, reserved-name checks, and all resource limits. Export uses two-space indentation, LF line endings and a final newline, within 5 MiB of UTF-8.
- Process documents locally after app assets load, without an account, backend, AI key, external font or automatic document-controlled network requests. Raw Markdown HTML and images are disabled. The schema validator is precompiled so production startup does not require `unsafe-eval`.

## Package

`glyf-viewer-0.1.0-rc.2.tar.gz` contains the static `site/`, this draft, a package README, the branded demo and authoritative working schema, dependency notices, source-input fingerprints, a build manifest and internal checksums. An adjacent manifest and `SHA256SUMS` identify the archive without extracting it. The archive is a viewer distribution; `.glyf` documents remain plain JSON, not compressed containers.

## Known limitations and release conditions

- Offline use starts after assets load. There is no cold-offline startup, service worker or supported `file://` launch. Serve `site/` at an HTTP(S) origin root. The tested CSP permits inline styles for layout/theme.
- Download creates a new browser-managed file; the saved indicator marks download initiation. There is no autosave, refresh recovery or tab-close/navigation guard. Confirm the download completed before closing. Invalid drafts are excluded; formatted output can exceed the byte limit even when a compact input fits.
- Source is read-only. Editing covers existing cells and state, not document structure, row insertion, formulas, arbitrary precision, rich conversion, collaboration or AI-service integration.
- Markdown parsing is synchronous. Extreme valid nesting can display escaped source instead of formatting; the depth guard is not a parsing deadline. Performance measurements do not establish latency bounds for every valid document.
- The repeated-replacement memory target remains unconfirmed: browser-native retention persists despite bounded application object lifetimes in the recorded investigation. A supported-platform/memory disposition is still needed.
- Automated Chromium/WebKit workflows and an installed-Brave run provide coverage, not universal browser certification. Actual VoiceOver output, native file dialogs and the remaining manual browser checks are incomplete; physical-mobile and Windows verification remain open.
- The Glyf brand and `.glyf` suffix are selected, but clearance remains unresolved for the intended worldwide release. Existing software uses Glyf and the same spelling is a font-table tag; see the repository naming report. The repository has no project license file yet; distribution terms remain a separate release decision. Included dependency notices do not choose a license for Glyf itself.

These conditions remain visible for candidate evaluation. Packaging does not mark the public-release gates complete, publish an npm package, create a Git tag, or deploy a site.
