**Reviewed: 2026-11-19. Candidate: `0259136`**, including the `90c2723` rendering improvement. Format version is **`0.1.0`**. This reporting step changes documentation only; application code, schema, dependencies and format limits are unchanged.

**The ten implementation Definition of Done statements have supporting evidence. The review did not publish, tag, push or deploy a release.

## Remaining limitations and deployment gates

| ID                                  | Finding                                                                                                                                                                                                                         | Release impact / required follow-up                                                                                                                                                                                                                                                                                                       |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| R1 — Memory stability               | 100-cycle JS drift remains; 500-cycle snapshots attribute most JS growth to VM warmup, while native media-query structures continue growing under Chromium's StyleEngine.                                                       | **Unconfirmed engineering target.** No leak-free claim. Carry the limit in release notes; use longer runs and additional browser versions before strengthening the claim. Details: [profiling report](performance-improvements.md#memory-investigation-and-disposition).                                                                  |
| R2 — Strict CSP                     | [schema.ts](../src/core/schema.ts) compiles the trusted bundled schema at startup. Ajv uses runtime code generation. A production policy with `script-src 'self'` and no `unsafe-eval` prevented startup in the tested browser. | **Gate for hosts requiring that policy.** Precompile the validator or otherwise resolve compatibility before deploying under such a CSP. This record does not recommend silently weakening a host's policy. No hosting policy or actual deployment was changed or approved.                                                               |
| R3 — Development dependencies       | The full audit reports 8 moderate findings rooted in [GHSA-g3hv-75wg-m249](https://github.com/advisories/GHSA-g3hv-75wg-m249), affecting minimatch 10.2.6 through ESLint/TypeScript ESLint. Production audit is clear.          | **Known development-tool risk.** Document data is not passed to these glob tools. npm suggests ESLint 10.15.0 / typescript-eslint 8.73.0 updates; those suggestions were not installed or validated. Schedule a controlled dependency update and rerun checks. The Phase 0 nine-finding report is historical; the current count is eight. |
| R4 — Startup/offline scope          | Offline operation begins after the app assets load. There is no service worker/cold-offline startup or supported `file://` deployment.                                                                                          | Static HTTP(S) asset delivery is required initially; local processing needs no backend. Clicking an allowed HTTP(S)/mailto link intentionally leaves the offline document flow.                                                                                                                                                           |
| R5 — Browser/accessibility coverage | Automated Chromium/WebKit workflows, keyboard/focus/labels/live-region relationships, 320/375px layouts and 200% root text size are covered.                                                                                    | Actual VoiceOver/NVDA speech, Firefox, branded Safari/Chrome releases, OS file-dialog navigation and physical devices were not certified. See [accessibility.md](accessibility.md).                                                                                                                                                       |
| R6 — Performance envelope           | Measurements use a fast desktop, warm assets, simple synthetic Markdown, one dataset and two charts. The 500 kB uncompressed JS warning remains although gzip is below budget.                                                  | No universal latency/peak-memory claim for cold startup, 5 MiB worst cases, hostile Markdown, many charts, or fully expanded tables. See [benchmark scope](benchmarks.md#scope-and-release-interpretation).                                                                                                                               |
| R7 — Markdown robustness            | Parsing is synchronous before the AST-depth guard. Some extreme valid text falls back to escaped source when rendering fails.                                                                                                   | No CPU deadline/worker sandbox or full GFM promise. Rendering fallback preserves source and other document operations; it does not reject or rewrite the format.                                                                                                                                                                          |
| R8 — Saving and replacement         | Browser downloads create new files; the saved indicator records download initiation. There is no autosave, reload recovery or tab-close/navigation guard.                                                                       | Users must download committed changes. Replacement confirmations cover Open Demo/File/drop; invalid drafts are neither committed nor exported. Compact files can open but exceed 5 MiB once formatted for export.                                                                                                                         |
| R9 — Data and authoring scope       | JSON numbers use JavaScript precision; source formatting/number spelling is not retained. Source is read-only and editing covers existing cells/state only.                                                                     | No arbitrary-precision promise, migrations, structural editor, row insertion/deletion, formulas or general import/export conversions. See [compatibility.md](compatibility.md).                                                                                                                                                           |
| R10 — Public naming                 | The spec explicitly calls for working-name/extension collision and trademark checks before public launch.                                                                                                                       | Those checks were not performed by this implementation review. No public-launch clearance is claimed.                                                                                                                                                                                                                                     |

The strict-CSP probe injected this response policy into the local production preview: `default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; connect-src 'none'; object-src 'none'; base-uri 'none'`. The observed failure was string evaluation blocked by `script-src`; the viewer did not mount. This tests one concrete policy, not every possible host configuration. Document content remains data; the generated validator code comes from the trusted bundled schema.

## Compatibility and scope

The [v0.1 compatibility contract](compatibility.md) records exact version handling, all 14 node kinds, schema/semantic enforcement, numeric/state/dataset/chart rules, fixed inclusive limits, Markdown/URL behavior, export formatting and errors. Future versions remain explicitly outside this release: no AI-service integration, executable document components, assets, compressed containers, formulas, canvas, collaboration or cloud synchronization.

All six implementation phases now have recorded deliverables and verification. Remaining work is the explicit follow-up/deployment work above; completion of the implementation checklist does not erase those conditions or authorize publishing.
