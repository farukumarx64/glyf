## Strict-CSP follow-up — 2026-11-20

The [generator](../scripts/generate-validator.ts) compiles the authoritative Draft 2020-12 schema using the original strict, non-mutating Ajv settings. It bundles Ajv's standalone output and Unicode-length helper into an ignored, self-contained ES module. [schema.ts](../src/core/schema.ts) imports this module; resource preflight, semantic validation, error selection and JSON Pointer construction are unchanged. The compiler runs only in build/dev/test preparation, with no runtime fallback. No package version or format contract changed.

The [compatibility tests](../tests/standalone-validator.test.ts) compare acceptance and complete diagnostic arrays with the original compiler, including every node kind, invalid unions, pointer escapes, Unicode boundaries, finite numbers, own-property handling, resource bounds and unchanged inputs. Existing format tests continue to exercise the public validation and serialization APIs.

The [production regression](../tests/browser/csp.spec.ts) first reproduced the old startup failure, then passed in Chromium and WebKit. It asserts the actual CSP response header and disables CSP bypass. After assets load, it goes offline and checks Open Demo, Markdown, table/chart edits, state/conditional updates, parser/schema/semantic rejection with preserved edits, Source, formatted download and reopen. Both engines report zero page errors, CSP violations and document-related requests. The policy disallows string evaluation and inline scripts while retaining inline styles for the existing layout/theme.

Verification used a fresh snapshot of the uncommitted working tree with **no generated validator or `node_modules`**. `npm ci --offline --cache /private/tmp/mosaic-npm-cache --no-audit --no-fund` installed 286 locked packages. `npm run check` generated the module and passed strict TypeScript, lint, formatting, **607 tests in 29 files**, reference-demo validation and production build. The new validator and JS/CSS assets were byte-identical to those from the main checkout. Repeated generation also preserved the unchanged output's bytes and timestamp. The normal development command launched successfully; demo validation, rendering and a state edit worked without page errors.

The complete production suite passed **68/68 Chromium/WebKit tests in 15.6 seconds** on the final run. The initial full run passed 67/68: the existing Chromium dark keyboard workflow timed out waiting for a file chooser after a reopen. That unchanged test passed three isolated traced runs and the full rerun; the timeout's cause was not established and no unrelated application or test fix was made. Both strict-CSP regressions passed throughout the runs with the precompiled validator.

The current bundle is **119.95 KiB gzip JavaScript**, down from 150.60 KiB, measured with the same compressor settings. The old timing/memory samples remain explicitly tied to the prior build. See [the bundle follow-up](benchmarks.md#strict-csp-bundle-follow-up--2026-11-20).
